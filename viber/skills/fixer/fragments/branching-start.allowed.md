- Any `error:` line -> show every one, ask nothing here; hand off no branch line.
- A `suggested:` entry other than `none` -> take it without a question.
- Otherwise ask which entry the run uses, offering only `entry:` lines reading `usable: yes`, plus "no branch". Describe each option by its `base:`, `name:` pattern and `target:`. An `entry:` line reading `usable: no` waits for an issue number: never offer it. No usable entry -> say so and hand off no branch line: the planner settles the entry once the run carries an issue, a saved one included.
- Once an entry is settled, a `suggested:` one included, show one run branch line in the conversation's language, never opening with `Work:` or `Branch:`: the entry key, its branch (the `name:` pattern), its `base:` and its `target:`. "no branch" -> no base check, and the line says there is no run branch and commits land on `current:`.
- The chosen entry's `at-base: yes` -> go on. `at-base: no` -> ask: switch to its `base:`, stay on `current:`, or abort. Name how many commits the base is behind its remote when `behind:` is above 0, and that uncommitted changes block the switch when `dirty: yes`. On `base-exists: no` name the missing base and never offer "switch".
- "switch" -> run `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --checkout "<branch>"` as one literal Bash line. Exit 6 -> show its error. Before the reproduction test exists, tell the user to commit or stash first and ask the same question again; once it exists, the uncommitted reproduction test is what blocks the switch, so ask only stay or abort.
- "stay" -> go on from `current:`; the line says there is no run branch and commits land on `current:`. "abort" -> stop and run nothing else.
- When the save step creates an issue, run the step again right after that save and before the hand-off, with the `ISSUE_URL=` value of that save: `"${CLAUDE_PLUGIN_ROOT}/scripts/plan-path.sh" --start "<ISSUE_URL>"` as one literal Bash line. No save made, `mode: off` earlier or the report read from an issue -> do not run it again. Its `error:` lines (an issue with no type, or one no mapping names) -> show every one and keep the earlier settlement. A `suggested:` entry other than `none` -> it replaces the earlier settlement, "no branch" included, announced by the run branch line, then the base check above with every answer as before. `suggested: none` -> keep the earlier entry or "no branch" and ask nothing; when nothing was settled, ask among the `usable: yes` entries as above. Never announce the same entry twice.
