viber

From an idea to committed code in four steps: understand it, plan it, build it, remember it. Nothing is built before you approve the plan.

Od pomysłu do zacommitowanego kodu w czterech krokach: zrozum, zaplanuj, zbuduj, zapamiętaj. Nic nie powstaje, zanim nie zatwierdzisz planu.

CLAUDE.md

viber knows nothing about your stack. Every agent takes the build and test commands from this project's own instructions, so without them test-runner guesses from whatever manifest it finds, and a task can be committed on a suite that never ran.

viber nic nie wie o twoim stosie technologicznym. Każdy agent bierze polecenia budowania i testów z instrukcji tego projektu, więc bez nich test-runner zgaduje na podstawie manifestu, który akurat znajdzie, a zadanie może zostać zacommitowane na testach, które nigdy się nie uruchomiły.

No CLAUDE.md yet: run /init, then make sure the root file states the exact build command, the exact test command, how to run a single test file, and whatever else a newcomer would get wrong, such as how to launch the app, the required env or the migrations. When your test command also runs the end-to-end tests, name one that leaves them out: a build never runs them unless you ask.

Nie masz jeszcze CLAUDE.md? Uruchom /init, a potem upewnij się, że główny plik podaje dokładne polecenie budowania, dokładne polecenie testów, sposób uruchomienia pojedynczego pliku testów i wszystko inne, co nowa osoba w projekcie zrobiłaby źle: jak uruchomić aplikację, jakich zmiennych środowiskowych potrzeba, jak wykonać migracje. Jeśli twoje polecenie testów uruchamia też testy end-to-end, podaj takie, które je pomija: build nigdy ich nie uruchamia, chyba że o to poprosisz.

The ways inPunkty wejścia

/viber:triage
Comes before any of them. It checks one reported issue (a GitHub number, a link or pasted text) against the code and names the next step: /viber:fixer, /viber:intent or none. It starts nothing itself and posts its report on the issue only when you say so.Idzie przed każdym z nich. Sprawdza jedno zgłoszone issue (numer z GitHuba, link albo wklejony tekst) względem kodu i wskazuje następny krok: /viber:fixer, /viber:intent albo żaden. Sam niczego nie uruchamia, a raport publikuje na issue tylko wtedy, gdy o to poprosisz.
/viber:intent
An interview about a raw idea, one question at a time. No production code; when the issues switch is on, it can save its confirmed summary as a new issue.Wywiad o surowym pomyśle, jedno pytanie naraz. Żadnego kodu produkcyjnego; gdy przełącznik issues jest włączony, może zapisać potwierdzone podsumowanie jako nowe issue.
/viber:fixer
A bug traced to its root cause and proven by a failing test.Błąd prześledzony do przyczyny źródłowej i udowodniony testem, który nie przechodzi.
/viber:prototype
A UI change becomes one working HTML mockup in your project's own look, or three alternatives to choose from; it asks which one you want before it starts. You refine it in conversation, then its conclusions go on to /viber:intent, onto the GitHub issue it started from, or both. Mockups land in .temp/viber/prototype/.Zmiana w UI staje się jedną działającą makietą HTML w wyglądzie twojego projektu albo trzema wariantami do wyboru; na początku pyta, którą opcję wybierasz. Dopracowujesz ją w rozmowie, a potem wnioski trafiają do /viber:intent, na issue na GitHubie, od którego wyszedł prototyp, albo w oba miejsca. Makiety lądują w .temp/viber/prototype/.

intent and fixer both hand off to the planner, and prototype hands off to intent.

intent i fixer przekazują pracę planiście, a prototype przekazuje ją do intent.

To continue a plan that stopped at a draft, with no tasks yet, point /viber:intent at it. To resume a build interrupted halfway, ask Claude to continue the build; it reopens the run most recently worked on.

Plan, który zatrzymał się na szkicu, jeszcze bez zadań, kontynuujesz, wskazując na niego /viber:intent. Przerwany w połowie build wznowisz, prosząc Claude o kontynuację buildu; otworzy się wtedy przebieg, nad którym pracowano ostatnio.

From a GitHub issueZ issue na GitHubie

With the issues switch on, one issue can carry a change from report to commit:

Przy włączonym przełączniku issues jedno issue może poprowadzić zmianę od zgłoszenia aż do commita:

  1. /viber:triage #42 checks the issue against the code and names the next step./viber:triage #42 sprawdza issue względem kodu i nazywa następny krok.
  2. /viber:intent, /viber:fixer or /viber:prototype, given #42, a link or the bare number, reads that issue instead of you restating it, then keeps working on the same issue. An interview that did not start from one can, once confirmed, save its summary as a new issue built from your project's own issue templates; /viber:intent #42 later resumes it./viber:intent, /viber:fixer albo /viber:prototype z argumentem #42, linkiem lub samym numerem czyta to issue, zamiast kazać ci je streszczać, i dalej pracuje na tym samym issue. Wywiad, który nie zaczął się od issue, może po potwierdzeniu zapisać swoje podsumowanie jako nowe issue, zbudowane z szablonów issue twojego projektu; /viber:intent #42 później go wznawia.
  3. The plan and its specification keep the issue.Plan i jego specyfikacja zachowują powiązanie z issue.
  4. Every commit of the build ends with Refs: #42, so GitHub links each one to the issue once pushed.Każdy commit buildu kończy się linią Refs: #42, więc po wypchnięciu GitHub pokazuje każdy z nich w issue.

A task commit from a run tied to issue #42.Commit zadania z przebiegu powiązanego z issue #42.

/viber:prototype started from an issue can post its conclusions there as a comment. Attach the mockup to that comment yourself in the browser: only the browser accepts an HTML attachment.

/viber:prototype uruchomiony z issue może opublikować tam swoje wnioski jako komentarz. Makietę dołącz do tego komentarza samodzielnie w przeglądarce: tylko przeglądarka przyjmuje załącznik HTML.

After a buildPo buildzie

/viber:e2e needs qawymaga qa
Turns the QA scenarios a build wrote into Playwright tests, run against your own application and committed once they are green. Needs the qa switch to have been on during that build, and that switch is off by default, so turn it on before the build starts.Zamienia scenariusze QA zapisane przez build w testy Playwright, uruchamiane na twojej aplikacji i commitowane, gdy przechodzą. Wymaga, żeby przełącznik qa był włączony podczas tego buildu, a domyślnie jest wyłączony, więc włącz go przed rozpoczęciem buildu.

On your own scheduleWe własnym rytmie

/viber:memory
Maps this project's CLAUDE.md cascade, verifies it against the code through a dispatched auditor, and hands what changed to a node writer.Mapuje kaskadę CLAUDE.md tego projektu, weryfikuje ją względem kodu przez osobnego agenta audytora i przekazuje zmiany agentowi piszącemu węzły.
/viber:rules
Maps .claude/rules/, verifies it the same way, and hands what changed to the same writer the build close uses.Mapuje .claude/rules/, weryfikuje je w ten sam sposób i przekazuje zmiany temu samemu autorowi, którego używa zamknięcie buildu.

Both ask before writing anything and leave the result unstaged, as the build close does. Neither needs a build in progress, so run them whenever the layer might have drifted. Both also offer a reset mode, which deletes the whole layer and starts from zero; it is refused while a target holds uncommitted work.

Oba pytają, zanim cokolwiek zapiszą, i zostawiają wynik poza indeksem gita (unstaged), tak jak zamknięcie buildu. Żaden nie wymaga trwającego buildu: uruchamiaj je, gdy ta warstwa mogła się rozjechać z kodem. Oba oferują też tryb reset, który usuwa całą warstwę i zaczyna od zera; jest odrzucany, gdy cel ma niezacommitowane zmiany.

issues onwł.
intent, fixer, prototype and triage can start from a GitHub issue by number or link, an interview that did not start from one can save its conclusions as a new issue, and a build tied to an issue ends every commit with Refs: #<N>. Off, triage only assesses pasted issue text.intent, fixer, prototype i triage mogą zacząć od issue na GitHubie, podanego numerem lub linkiem; wywiad, który nie zaczął się od issue, może zapisać swoje wnioski jako nowe issue, a build powiązany z issue kończy każdy commit linią Refs: #<N>. Przy wyłączonym przełączniku triage ocenia tylko wklejony tekst issue.

Six of the seven start on. qa starts off, because most builds need no acceptance scenarios. To change any of them, edit .claude/viber.yml: every key has a comment there, and only true counts as on. Turn a switch off with false instead of deleting it. Running /viber:setup again merges in every key the current version's template has and your file lacks. That is how a new switch reaches a project set up by an older version, and the same merge restores a deleted top-level key, or a deleted directories: child, at its default. Children of tiers: and branching: work differently: the merge adds either group only as a whole, when the file lacks it entirely, and never extends one already present. A child you delete there does not come back into the file; it simply resolves to its default. The merge keeps every value you have already set.

Sześć z siedmiu jest domyślnie włączonych. qa jest wyłączony, bo większość buildów nie potrzebuje scenariuszy akceptacyjnych. Zmienisz to w .claude/viber.yml: każdy klucz ma tam komentarz, a za włączony liczy się tylko true. Przełącznik wyłączaj wartością false, nie usuwaj go. Ponowne uruchomienie /viber:setup dołącza każdy klucz, który ma szablon bieżącej wersji, a którego brakuje w twoim pliku. Tak nowy przełącznik trafia do projektu skonfigurowanego starszą wersją i tak samo wraca z wartością domyślną usunięty klucz najwyższego poziomu albo usunięte dziecko grupy directories:. Dzieci grup tiers: i branching: działają inaczej: scalanie dodaje taką grupę tylko w całości, gdy w pliku jej w ogóle brakuje, i nigdy nie rozszerza już istniejącej. Usunięty tam klucz nie wraca do pliku, po prostu obowiązuje jego wartość domyślna. Scalanie zachowuje każdą już ustawioną wartość.

When your .claude/settings.json already exists, /viber:setup asks whether to merge the recommended permissions into it (viber's value wins a conflict, permission lists only gain entries) or reset it to the recommended file from scratch. A reset keeps your old file in .temp/viber/setup/settings.json.bak.

Gdy .claude/settings.json już istnieje, /viber:setup pyta, czy scalić z nim zalecane uprawnienia (wartość viber wygrywa konflikt, listy uprawnień tylko się rozszerzają), czy zresetować go i zapisać zalecany plik od zera. Reset zachowuje stary plik w .temp/viber/setup/settings.json.bak.

TiersPoziomy modeli

min haiku
The cheapest model the build dispatches.Najtańszy model, jaki uruchamia build.
max opus
The strongest one it may reach.Najmocniejszy, po jaki może sięgnąć.

A tiers: group, each value one of haiku, sonnet, opus or fable. Every task, review and retry is kept inside that range; fable runs only when the range names it. An unknown value falls back to its default and an inverted range to the default one. Planning runs on the session's own model and is not bound by it.

Grupa tiers:, każda wartość to jedna z: haiku, sonnet, opus lub fable. Każde zadanie, recenzja i ponowienie mieści się w tym zakresie; fable działa tylko wtedy, gdy zakres go wymienia. Nieznana wartość wraca do domyślnej, a odwrócony zakres do zakresu domyślnego. Planowanie działa na modelu bieżącej sesji i zakres go nie ogranicza.

BranchingGałęzie

mode off
off stays on the branch the run started on. allowed offers a branch during planning and waits for your confirmation. required always gives the run its own branch.off zostawia przebieg na gałęzi, na której się zaczął. allowed proponuje gałąź podczas planowania i czeka na twoje potwierdzenie. required zawsze daje przebiegowi własną gałąź.
work
Each kind of run branch a project wants, keyed by a short name: its own base it is cut from, name pattern (quoted since it opens on {) and target it would land a pull request on.Każdy rodzaj gałęzi przebiegu, jaki potrzebuje projekt, pod krótkim kluczem: własny base, z którego jest wycinana, wzorzec name (w cudzysłowie, bo zaczyna się od {) i target, na który trafiłby pull request.
issue-type-mappings
Picks a work entry by the type of the GitHub issue a run starts from (needs issues: true). Without a matching mapping, the single usable entry is offered instead.Wybiera wpis work na podstawie typu issue z GitHuba, od którego zaczyna się przebieg (wymaga issues: true). Bez pasującego mapowania proponowany jest jedyny możliwy do użycia wpis.

A name pattern is filled in from the plan: {type}, {slug} and {issue-number}. The last needs issues: true, since without it there is no issue number to fill in. viber never fetches, pushes, merges or deletes anything: it only creates a branch, switches to it and commits on it. A bad entry or mapping is dropped with a readable reason and the rest of the file still applies; see viber/BRANCHING.md for the full list. Each example below is a complete setup for one strategy; the strategy's name itself is never a configuration value.

Wzorzec name jest wypełniany na podstawie planu: {type}, {slug} i {issue-number}. Ten ostatni wymaga issues: true, bo bez tego nie ma numeru issue do wstawienia. viber niczego nie pobiera (fetch), nie wypycha (push), nie scala ani nie usuwa: tylko tworzy gałąź, przełącza się na nią i na niej commituje. Błędny wpis lub mapowanie jest odrzucane z czytelnym powodem, a reszta pliku nadal obowiązuje; pełną listę znajdziesz w viber/BRANCHING.md. Każdy przykład poniżej to pełna konfiguracja jednej strategii; sama nazwa strategii nigdy nie jest wartością konfiguracji.

Trunk based development, branching offTrunk based development, gałęzie wyłączone

branching:
  mode: off

Every run keeps committing on whichever branch you already checked out.

Każdy przebieg commituje na gałęzi, która jest już wybrana.

Trunk based development, short-lived branchesTrunk based development, krótko żyjące gałęzie

branching:
  mode: allowed
  work:
    main:
      base: main
      name: '{type}/{slug}'
      target: main

One entry, cut from and landing back on main. With allowed, each run asks you to confirm its branch.

Jeden wpis, wycinany z main i tam wracający. Przy allowed każdy przebieg prosi cię o potwierdzenie swojej gałęzi.
