# Shell preload contract

- A script named in a SKILL.md `!` preload keeps mode 100755 and is invoked DIRECTLY by its quoted path, never through an interpreter: ``!`"${CLAUDE_PLUGIN_ROOT}/scripts/read-config.sh"` `` in `superdev/skills/intent/SKILL.md`, and the fenced ```` ```! ```` block form in `viber/skills/implementor/SKILL.md`. All nine preload-invoked scripts are 100755: superdev's `read-config.sh`, `last-commit-date.sh`, `check-playwright.sh` and `skills/setup/scripts/bootstrap.sh`; supergh's `shared/scripts/preflight.sh` and `skills/commit/scripts/commit-context.sh`; viber's `scripts/config.sh`, its own `scripts/check-playwright.sh` and `skills/setup/scripts/bootstrap.sh`. A preload addressed through `${CLAUDE_SKILL_DIR}` rather than `${CLAUDE_PLUGIN_ROOT}` (both `setup` skills) needs its own `allowed-tools` pattern spelled the same way.
- The same two requirements (exec bit, direct invocation) bind a RUNTIME call - a bundled script a skill has the model run via the `Bash` tool mid-session, not as a preload. superdev's `commit-task.sh`, `decompose.sh`, `cleanup-run.sh`, `stats-record.sh`, `stats-report.sh`, `checkpoint-update.sh` and `record-decision.sh` and viber's `plan-path.sh`, `plan-index.sh`, `commit-task.sh` and `skills/setup/scripts/merge-settings.sh` are all 100755, and every call site (`superbuild/SKILL.md`, `simplebuild/SKILL.md`, both `e2e/SKILL.md`, `implementor/SKILL.md`, `planner/SKILL.md`, `setup/SKILL.md`) writes the literal line `"${CLAUDE_PLUGIN_ROOT}/scripts/<name>.sh" <args>` - never `bash "${CLAUDE_PLUGIN_ROOT}/..."`, never assigned to a variable, never preceded by `cd`, never chained with `;`. The permission classifier matches the literal prefix pre-approved in `allowed-tools`; any other form of the same command is a new, unapproved classification.
- A script invoked through an explicit interpreter does not need the exec bit; whether it carries one is then irrelevant and both shapes ship. `superdev/hooks/hooks.json` runs `bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/session-start.sh"` over a 100644 file, `viber/hooks/hooks.json` runs its two the same way over 100755 files, and `supercc`'s `lint_skill.sh` is 100644 and called as `bash "${CLAUDE_SKILL_DIR}/scripts/lint_skill.sh"` from the skill body. The interpreter form itself is the exception, reserved for hook wiring and for `supercc`'s linter, which is not pre-approved at all - it does not apply to a script a skill invokes as a preload or as a pre-approved runtime call.
- A preload script must NEVER exit non-zero on a data condition: a non-zero exit aborts the whole fork load and the fork receives none of its input. `read-config.sh` and `viber/scripts/config.sh` both run under `set -u` and end with a literal `exit 0` so a missing config file is fail-open, reserving a non-zero exit for a wiring bug alone. A preload that parses its own arguments follows the same shape: capture any failure-prone pipeline as `value="$(... || true)"` rather than letting `pipefail` kill the load.
- Choose the `set` line from the script's role and argue it in that script's header, rather than reaching for one habitually: of the 52 tracked scripts, 21 use `set -u` on its own (every hook, and every preload but `commit-context.sh`, which adds `pipefail`), 17 use `set -euo pipefail` (viber's `plan-path.sh`, `plan-index.sh` and `commit-task.sh` among them), and the remaining 14 split across `set -e`, `set -uo pipefail`, `set -eu` and no `set` line at all (every `lib_` file, plus scripts that handle their own exit codes). Under `pipefail`, never leave `head -n1` as the last command of a pipeline - it exits non-zero once it stops reading.
- Add a matching PATTERN entry to the skill's `allowed-tools` for every preload; a bare `Bash` allow does not cover an inline `!` command.
- Single-quote any preload argument containing `?`, `*` or `[`. The host shell parses the inline command before the script sees it, and zsh's default `nomatch` aborts the whole command, killing the fork load with no input, where bash would pass it through.
