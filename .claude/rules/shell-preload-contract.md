# Shell preload contract

- A script named in a SKILL.md `!` preload keeps mode 100755 and is invoked DIRECTLY by its quoted path, never through an interpreter: the fenced ```` ```! ```` block form in `viber/skills/implementor/SKILL.md`. All nine preload-invoked scripts are viber's and 100755: `scripts/config.sh`, `scripts/run-clock.sh`, `scripts/switch-text.sh` (via `${CLAUDE_PLUGIN_ROOT}`, by `fixer`, `implementor`, `intent`, `planner`, `prototype` and `triage`), its own `scripts/check-playwright.sh`, `skills/setup/scripts/bootstrap.sh`, `skills/memory/scripts/memory-map.sh`, `skills/rules/scripts/rules-map.sh`, `skills/handoff/scripts/handoff-path.sh` and `skills/commit/scripts/commit-context.sh`, whose last two preloads pass the skill arguments single-quoted (`'$ARGUMENTS'`), since Claude Code substitutes it before the shell parses the line. A preload addressed through `${CLAUDE_SKILL_DIR}` rather than `${CLAUDE_PLUGIN_ROOT}` (viber's `setup`, `memory`, `rules` and `handoff` skills) needs its own `allowed-tools` pattern spelled the same way.
- The same two requirements (exec bit, direct invocation) bind a RUNTIME call - a bundled script a skill has the model run via the `Bash` tool mid-session, not as a preload. Every call site (`e2e/SKILL.md`, `implementor/SKILL.md`, `planner/SKILL.md`, `setup/SKILL.md`, `agents/closeout.md`) writes the literal line `"${CLAUDE_PLUGIN_ROOT}/scripts/<name>.sh" <args>` - never `bash "${CLAUDE_PLUGIN_ROOT}/..."`, never assigned to a variable, never preceded by `cd`, never chained with `;` - covering `plan-path.sh`, `plan-index.sh`, `commit-task.sh`, `run-clock.sh`, `archive-run.sh`, `merge-settings.sh` and `open-page.sh`. `memory/SKILL.md` and `rules/SKILL.md` make the same kind of call through `${CLAUDE_SKILL_DIR}` instead, re-running their own map script with `--reset <path> [<path>...]` then bare again. `viber/scripts/issue-facts.sh`, `post-comment.sh`, `issue-templates.sh` and `create-issue.sh` are called only that way, variously by `triage`, `intent`, `fixer` and `prototype`. The permission classifier matches the literal prefix pre-approved in `allowed-tools`; any other form is a new, unapproved classification.
- A script invoked through an explicit interpreter needs no exec bit; both shapes ship. `viber/hooks/hooks.json` runs its three as `bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.sh"` over 100755 files, and `supercc`'s `lint_skill.sh` is 100644 and called as `bash "${CLAUDE_SKILL_DIR}/scripts/lint_skill.sh"` from the skill body. The interpreter form is the exception, reserved for hook wiring and `supercc`'s linter (not pre-approved at all) - never a preload or a pre-approved runtime call.
- A preload script must NEVER exit non-zero on a data condition: a non-zero exit aborts the whole fork load. `viber/scripts/config.sh` ends with a literal `exit 0` so a missing config file is fail-open, reserving a non-zero exit for a wiring bug alone; a preload that parses its own arguments captures any failure-prone pipeline as `value="$(... || true)"` rather than letting `pipefail` kill the load.
- Choose the `set` line from the script's role, argued in that script's header: most scripts use `set -u` alone (every hook, and every preload but `commit-context.sh`, which adds `pipefail`); a script whose steps must not continue past a failure uses `set -euo pipefail` instead (viber's `plan-path.sh`, `plan-index.sh`, `commit-task.sh`, `archive-run.sh`); the rest handle their own codes. Under `pipefail`, never leave `head -n1` as the last command of a pipeline - it exits non-zero once it stops reading.
- Single-quote any preload argument containing `?`, `*` or `[`. The host shell parses the inline command before the script sees it, and zsh's default `nomatch` aborts the whole command, killing the fork load with no input, where bash would pass it through.
