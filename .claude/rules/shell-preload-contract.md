# Shell preload contract

- A script named in a SKILL.md `!` preload keeps mode 100755 and is invoked DIRECTLY by its quoted path, never through an interpreter: the fenced ```` ```! ```` block form in `viber/skills/implementor/SKILL.md`. Viber's preload scripts (`scripts/config.sh`, `run-clock.sh`, `switch-text.sh` via `${CLAUDE_PLUGIN_ROOT}`, `open-page.sh`, `check-playwright.sh`, `skills/setup/scripts/bootstrap.sh`, `skills/memory/scripts/memory-map.sh`, `skills/rules/scripts/rules-map.sh`, `skills/handoff/scripts/handoff-path.sh`, `skills/commit/scripts/commit-context.sh`) are all 100755; the last two pass the skill arguments single-quoted (`'$ARGUMENTS'`), since Claude Code substitutes it before the shell parses the line. A preload addressed through `${CLAUDE_SKILL_DIR}` rather than `${CLAUDE_PLUGIN_ROOT}` needs its own `allowed-tools` pattern spelled the same way.
- The same two requirements (exec bit, direct invocation) bind a RUNTIME call, a bundled script the model runs via `Bash` mid-session. Every call site writes the literal line `"${CLAUDE_PLUGIN_ROOT}/scripts/<name>.sh" <args>` - never `bash "${CLAUDE_PLUGIN_ROOT}/..."`, never assigned to a variable, never preceded by `cd`, never chained with `;`: `plan-path.sh` in `planner/SKILL.md`, and likewise `commit-task.sh`, `archive-run.sh`, `issue-facts.sh`, `issue-templates.sh`, `issue-create.sh`, `pr-facts.sh`, `pr-create.sh`. `memory/SKILL.md` and `rules/SKILL.md` make the same kind of call through `${CLAUDE_SKILL_DIR}`. The permission classifier matches the literal prefix pre-approved in `allowed-tools`; any other form is a new, unapproved classification.
- A script invoked through an explicit interpreter needs no exec bit. `viber/hooks/hooks.json` runs its three as `bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.sh"` over 100755 files, and `supercc`'s `lint_skill.sh` is 100644 and called as `bash "${CLAUDE_SKILL_DIR}/scripts/lint_skill.sh"`. The interpreter form is reserved for hook wiring, `supercc`'s linter and `viber/skills/code-auditor/SKILL.md`, which pre-approves bare `Bash` and calls its scripts through `sh`, `bash` or `node`.
- A preload script must NEVER exit non-zero on a data condition: a non-zero exit aborts the whole fork load. `viber/scripts/config.sh` ends with a literal `exit 0` so a missing config file is fail-open, reserving a non-zero exit for a wiring bug alone; a preload that parses its own arguments captures any failure-prone pipeline as `value="$(... || true)"` rather than letting `pipefail` kill the load.
- Choose the `set` line from the script's role, argued in its header: most scripts use `set -u` alone (every hook, and every preload but `commit-context.sh`, which adds `pipefail`); a script whose steps must not continue past a failure uses `set -euo pipefail` (`plan-path.sh`, `commit-task.sh`, `archive-run.sh`). Under `pipefail`, never leave `head -n1` as the last command of a pipeline - it exits non-zero once it stops reading.
- Single-quote any preload argument containing `?`, `*` or `[`. The host shell parses the inline command before the script sees it, and zsh's default `nomatch` aborts the whole command, killing the fork load with no input, where bash would pass it through.
