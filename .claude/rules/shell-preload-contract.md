# Shell preload contract

- A script named in a SKILL.md `!` preload keeps mode 100755 and is invoked DIRECTLY by its quoted path, never through an interpreter: the fenced ```` ```! ```` block form in `viber/skills/implementor/SKILL.md`. All eight preload-invoked scripts are 100755: supergh's `shared/scripts/preflight.sh` and `skills/commit/scripts/commit-context.sh`; viber's `scripts/config.sh`, `scripts/run-clock.sh`, its own `scripts/check-playwright.sh`, `skills/setup/scripts/bootstrap.sh`, `skills/memory/scripts/memory-map.sh` and `skills/rules/scripts/rules-map.sh`. A preload addressed through `${CLAUDE_SKILL_DIR}` rather than `${CLAUDE_PLUGIN_ROOT}` (viber's `setup`, `memory` and `rules` skills) needs its own `allowed-tools` pattern spelled the same way.
- The same two requirements (exec bit, direct invocation) bind a RUNTIME call - a bundled script a skill has the model run via the `Bash` tool mid-session, not as a preload. viber's `plan-path.sh`, `plan-index.sh`, `commit-task.sh`, `run-clock.sh` (both a preload and a runtime call - the same script, called the same literal way at both ends of a build), `archive-run.sh` (closeout's runtime call at the end of a build) and `skills/setup/scripts/merge-settings.sh` are all 100755, and every call site (`e2e/SKILL.md`, `implementor/SKILL.md`, `planner/SKILL.md`, `setup/SKILL.md`, `agents/closeout.md`) writes the literal line `"${CLAUDE_PLUGIN_ROOT}/scripts/<name>.sh" <args>` - never `bash "${CLAUDE_PLUGIN_ROOT}/..."`, never assigned to a variable, never preceded by `cd`, never chained with `;`. `memory/SKILL.md` and `rules/SKILL.md` make the same kind of runtime call through `${CLAUDE_SKILL_DIR}` instead: on approval each runs its own map script a second time with `--reset <path> [<path>...]`, then bare again to refresh the map. The permission classifier matches the literal prefix pre-approved in `allowed-tools`; any other form of the same command is a new, unapproved classification.
- A script invoked through an explicit interpreter does not need the exec bit; whether it carries one is then irrelevant and both shapes ship. `viber/hooks/hooks.json` runs its two as `bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/<name>.sh"` over 100755 files, and `supercc`'s `lint_skill.sh` is 100644 and called as `bash "${CLAUDE_SKILL_DIR}/scripts/lint_skill.sh"` from the skill body. The interpreter form itself is the exception, reserved for hook wiring and for `supercc`'s linter, which is not pre-approved at all - it does not apply to a script a skill invokes as a preload or as a pre-approved runtime call.
- A preload script must NEVER exit non-zero on a data condition: a non-zero exit aborts the whole fork load and the fork receives none of its input. `viber/scripts/config.sh` runs under `set -u` and end with a literal `exit 0` so a missing config file is fail-open, reserving a non-zero exit for a wiring bug alone. A preload that parses its own arguments follows the same shape: capture any failure-prone pipeline as `value="$(... || true)"` rather than letting `pipefail` kill the load.
- Choose the `set` line from the script's role and argue it in that script's header, rather than reaching for one habitually: of the 29 shipped scripts, 17 use `set -u` on its own (every hook, and every preload but `commit-context.sh`, which adds `pipefail`), 8 use `set -euo pipefail` (viber's `plan-path.sh`, `plan-index.sh`, `commit-task.sh` and `archive-run.sh` among them), and the rest split across other `set` lines or none (scripts that handle their own exit codes). Under `pipefail`, never leave `head -n1` as the last command of a pipeline - it exits non-zero once it stops reading.
- Add a matching PATTERN entry to the skill's `allowed-tools` for every preload; a bare `Bash` allow does not cover an inline `!` command.
- Single-quote any preload argument containing `?`, `*` or `[`. The host shell parses the inline command before the script sees it, and zsh's default `nomatch` aborts the whole command, killing the fork load with no input, where bash would pass it through.
