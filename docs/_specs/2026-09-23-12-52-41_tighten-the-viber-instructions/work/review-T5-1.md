## Critical

- `viber/agents/test-runner.md:32` - The new "build failed" bullet ends with a dangling colon and no sub-bullets: `The build failed: write one line to the report path naming the build command and its first error line, then return with no test run:`. It never states which lines to return. DoD.1 requires "a failed build returns `VERDICT: FAIL`, `REPORT` and `FAILED`", but as written the agent has no instruction to emit those three return lines for a build failure - the only explicit `VERDICT: FAIL` / `REPORT:` / `FAILED: <count>` sub-bullets sit under the next, separate "Otherwise" bullet (line 33-36), which is about per-test failures ("write one line per failure ... test name, file, and the assertion or error"), not a build failure. Reading the contract as written, a build failure either produces no defined return lines at all, or an agent must guess that it should reuse the "Otherwise" bullet's sub-lines despite the prose never saying so and despite the per-failure wording not matching a build error. Fix by folding the build case into the same return format explicitly, e.g. merge the two bullets into one ("The build or a test failed: ... then return: - line 1: `VERDICT: FAIL` - line 2: `REPORT: <report path>` - line 3: `FAILED: <count>`, or `FAILED: 0` when the build itself failed before any test ran") so the contract names, for every failure path, exactly which lines are returned.
