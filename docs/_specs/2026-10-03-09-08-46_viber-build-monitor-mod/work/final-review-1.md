# Final review - slice 1 (T1-T6)

## Blocking

1. `viber/hooks/monitor/register.tsx:119-123` - the observed run's last task-done toast and its build-end toast are lost whenever any other unsettled run exists under the runs directory (an abandoned run that `plan-path.sh` lists as `open:` is enough). Once the observed run settles, `pickRun` skips it, so `view` is the other run; `now = view ?? ...` then holds the other run's index, and `diffEvents(seen.before, now)` returns `[]` because `next.plan !== prev.plan` (`viber/hooks/monitor/monitor.ts:180`). The settled index is already in `loaded` (the run that just committed is `plan-path.sh`'s newest `path:` plan, so `activeIndex` loads it), but it is only used when `view` is undefined. This breaks criterion 6 ("a toast appears ... when the run settles") and S6 for a common repository state. The T2 coder notes flagged the trap ("re-index `prev.plan` itself to see its own settle"); the T6 notes record the loss ("Another run taking the view while the observed one settles loses the build-end toast") and no test covers it. Fix: in `refresh`, when `seen.before` exists and `view` is undefined or `view.plan !== seen.before.plan`, diff against the observed run's own index: `loaded.get(seen.before.plan)`, loading it through `plan-index.sh` when `activeIndex` did not (`undefined` still meaning archived). Add a case to `tests/viber/monitor/register.test.tsx` with two unsettled runs where the observed one settles and the toasts `viber: T2 done (2/2)` and `viber build finished: 2/2 done` still appear.
