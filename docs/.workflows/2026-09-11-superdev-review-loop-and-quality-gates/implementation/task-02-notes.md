# Task 2 notes

- Rewrote the whole header comment of `commit-task.sh` in English instead of extending the existing Polish one, because the plan header's repo conventions require scripts in English.
- Every git call after the repository guard runs through `git -C <repository root>` (root from `git rev-parse --show-toplevel`), which Approach steps 3-4 do not mention, because the declared set is compared against `git status --porcelain` output that is always repository-root relative, and staging must resolve the same way from any cwd.
- `normalise_path()` also reduces an absolute path inside the repository to a root-relative one (on top of the `\` to `/` normalisation the Edge cases name), because the orchestrator is required to pass absolute paths and those would otherwise never match a porcelain path.
- Staging does not use the single `git add -A -- "${declared[@]}" ':(exclude).temp'` form of Approach step 4: git stops matching a directory pathspec as soon as any exclude pathspec joins it (verified on git 2.47.1), which would silently stage nothing for `--path <dir>`; instead `.temp` entries are dropped from the declared set and the exclude is used only in the whole-tree branch, `git add -A -- ':/' ':(exclude,top).temp'`, which was verified to work.
- A declared path that is untracked AND covered by `.gitignore` is dropped as well, not only one that "neither exists nor is tracked", because `git add` aborts fatally on an explicitly named ignored path and would take the whole commit down with it.
- A rename or copy entry in porcelain output is checked on both of its paths against the declared set, since the record carries the old path as well; the Approach describes only one path per entry.
- Two existing tests ("stages and commits a pending change", "newline, quote and non-ASCII") needed a baseline commit on top of the `--path a.txt` the Approach asks for, because `withGitRepo` leaves its own `.gitconfig-global` in the tree and the new undeclared check reports it - correctly - as a foreign change.
- Added one test beyond the six in the DoD (a `.gitignore`d untracked file is neither undeclared nor committed), because that is an Edge cases bullet with no other coverage.

- UNDERSPECIFIED: tolerance of the parsed line shapes - the `### Files` verb list and the `touched:` line are specified bare; decided to strip a leading `- ` or `* ` bullet marker and surrounding backticks from both, and to accept `create`, `remove` and `update` next to `add`, `modify` and `delete` as verbs, so a hand-written notes bullet still declares its path.
