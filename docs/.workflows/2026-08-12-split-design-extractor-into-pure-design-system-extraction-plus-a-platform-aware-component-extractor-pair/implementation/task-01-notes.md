- `parseFrontMatter` returns `{ frontMatter, body }` (a plain split on the opening `---` delimiters) rather than a parsed structured object of the YAML front matter — the Approach names the front matter a "derived subset" the body tables must not be sourced from, so the function's only real job is handing `parseBodyTables` a clean body string; a full YAML re-parse would be dead code with no consumer.
- a token's `type` field is not observable in a rendered table (render_design_md.ts never prints a Type column for any section) — `defaultTypeFor(sectionId, name)` assigns a fixed per-section value (color/fontFamily/dimension/shadow/gradient/duration/string) instead, documented in the header comment; no downstream consumer reads `type` for behavior, only build_registry.ts requires it non-empty, so this is a safe placeholder rather than a reconstruction.
- a proposed row's Notes cell combining `PROPOSED - <rationale>` with a trailing measured note (`tokenNotesCell`'s `parts.join("; ")` when both `rationale` and `notes` are set) is not split back apart — the whole remainder after `PROPOSED - ` is kept as `rationale` and no measured `notes` value is recovered for that row; out of contract in practice since a proposed token in this pipeline never also carries a measured note.
