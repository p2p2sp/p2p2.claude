# Concepting - the pre-layout concept brief

Read when: before building ANY new Persuade or Experience surface, before the layout skeleton exists - even
when the project already defines a design system (tokens bind palette, type, radius, spacing; they do not
supply a composition concept). Not required for Operate/Read surfaces (dashboards, forms, settings, admin
tables) where the job is task completion, not persuasion or experience.

## The concept brief

Write this out and show it to the user before any layout work. Six parts, 5-10 lines total:

1. Thesis - one sentence: what this page proves, not what it lists.
2. Subject world - 3-5 physical artifacts or rituals from the product's own domain (not generic tech
   iconography). Promote at least one to the page's main visual device - the thing the layout is built around.
3. Reference anchor - one narrow, out-of-web reference point (a craft, a discipline, a physical object class,
   an editorial tradition) justified by the subject world above. Never a stock or repeated anchor across
   briefs - it must be different each time and traceable to this specific subject.
4. Anti-references - 3 named things this page deliberately does NOT do, because everyone in this category
   does them. Each is a real, specific taboo for this subject, not a generic "no gradients" restatement.
5. Signature element + recurrence plan - the one bold element the page is remembered by, plus where it
   returns: at least 3 placements (hero, mid-page, CTA or footer), naming the form it takes at each spot
   (quieter returns are fine, but it must be present, not merely echoed in spirit).
6. Section sequence - the ordered list of sections, each tagged with a layout family (3-col cards,
   full-width quote, split text+image, asymmetric grid, horizontal scroll, and peers - families ->
   anti-slop.md).

## Skeleton critique

Before building, attack the sequence from part 6: would this same section sequence ship for any similar
product in this category? If yes, the outline itself is the default - redesign the sequence and the layout
families, not the cosmetics on top of it. A page that swaps colors and copy but keeps the same shape has not
passed this test.

This applies even when the project already has a design system: a token set fixes values, never the shape of
the page. Run the critique against the section sequence regardless of how settled the visual tokens are.

After the critique holds, derive every build decision - copy, imagery, motion, component choice - from the
revised brief. Nothing built before this point survives past it unexamined.
